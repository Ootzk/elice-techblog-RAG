# 🥇 Gold Set

한국어 엘리스 테크블로그를 근거로 답변하는 RAG QA의 검색·응답 품질을 평가하는 22문항 데이터셋이다. 도입 판단, 운영 문제 해결, 기술 비교처럼 실제 사용자의 상황에서 출발하는 질문으로 구성한다.

## 구성

| 유형 | 문항 수 | 평가 대상 |
| --- | ---: | --- |
| 단일 문서 기반 | 13 | 사실 확인, 수치·표 해석, 원인 진단, 활용 조언 |
| 문서 간 비교 | 1 | 서로 다른 모델 개선 사례의 비교 |
| 시리즈 종합 | 3 | 여러 글의 내용을 연결한 설명 |
| 후속 대화 | 1 | 앞선 대화의 지시 대상을 해석한 검색·답변 |
| 근거 부족 | 4 | 공개되지 않거나 문서에 없는 정보를 추측하지 않는 판단 |
| 합계 | 22 | 답변 가능 18문항, 근거 부족 4문항 |

시리즈 종합 문항은 한국어 소형 모델의 데이터 준비·학습·평가, GPU VM의 토폴로지·직접 통신, PWA의 설치·활성화·업데이트를 다룬다. 질문에서 글 제목이나 세부 실험 구성을 직접 지정하지 않고, 답변에 필요한 근거를 찾아 연결하도록 한다.

## 구축 방법

**저장된 문서에 근거한 LLM 보조 합성과 사람 검수를 결합했다.** 실제 사용자 질의 로그를 수집한 데이터셋이나 사람이 모든 초안을 직접 작성한 데이터셋은 아니다.

1. PostgreSQL에 저장된 고정 Corpus의 원문과 청크를 읽고 질문·답안에 사용할 내용을 확인했다. 공개 웹의 현재 페이지가 아니라 같은 스냅샷을 기준으로 작성했다.
2. GPT와 Claude가 작성한 질문·모범 답안 후보를 비교하고, 중복을 줄이면서 사실 확인·요약·원인 추론·문서 간 종합 문항을 선정·보완했다. 문서를 그대로 질문으로 바꾸기보다 도입·운영 상황에서 필요한 조언을 묻도록 합성했다.
3. 각 답안에 필수 요점·선택 사항·금지 주장과 출처를 붙였다. 긍정 근거 53개는 21개 문서에서 가져왔으며, 인용문이 해당 정책의 저장 청크에 실제로 포함되는지 대조했다.
4. 근거 부족 문항은 관련 문맥과 공개 범위를 확인해 작성했다. 단어 검색 결과가 없다는 사실만으로 답이 없다고 판단하지 않고, 다른 모델·실험 수치나 미래 계획을 요청한 사실로 잘못 옮겨 답할 가능성도 살폈다.
5. 사람이 전체 질문·모범 답안·수용 기준을 검수하고, 특정 글이나 실험 구성을 노골적으로 지정하는 표현을 줄였다. 후속 대화의 앞선 답변도 평가용으로 작성한 고정 이력이다.

생성 모델의 정확한 버전·샘플링 설정·전체 초안 생성 프롬프트를 재생성 가능한 형태로 보관하지는 않았다. 따라서 같은 초안을 다시 생성하는 재현성보다, 확정된 JSONL·내용 해시·Corpus 기준을 통한 **동일 입력 평가의 재현성**을 제공한다.

## 편향과 한계

| 구분 | 편향·한계와 결과 해석 시 주의점 |
| --- | --- |
| 출처·주제 | 한국어 엘리스 테크블로그 한 곳이며 GPU·LLM·보안·개발 사례에 집중한다. 다른 업체·언어·일반 지식의 QA 품질로 일반화할 수 없다. |
| 원문 주장 | 자사 제품 소개와 자체 벤치마크를 포함한다. 문서에 충실한 답변인지를 평가하며, 원문 주장의 객관적 진실이나 외부 재현성까지 보증하지 않는다. |
| 표본 크기·구성 | 22문항이며 실제 사용자 분포에서 무작위로 추출하지 않았다. 18개 답변 가능·4개 근거 부족이라는 비율도 설계된 구성이지 운영 발생률이 아니다. |
| 합성·검수자 | LLM이 문서에서 답을 정한 뒤 질문을 구성해 검색 가능한 정보와 익숙한 표현에 유리할 수 있다. 사람 검수를 거쳤지만 복수 독립 검수자의 일치도를 측정하지 않았다. |
| 근거 표현 | HTML 텍스트와 저장 청크를 중심으로 작성했다. 이미지·도표만의 정보, 추출되지 않은 내용과 대체 가능한 모든 정답 근거를 포괄하지 않는다. |
| 시점 | 특정 Corpus 스냅샷의 공개 정보에 한정한다. 이후 공개된 사양·가격·SLA는 기대 답안과 다를 수 있으며, 근거 부족도 스냅샷에 상대적인 판정이다. |
| 대화 | 후속 대화는 고정 이력 1문항뿐이다. 모델이 만든 답변을 이어 쓰는 긴 대화, 문맥 누적과 오류 전파를 평가하지 않는다. |
| 개발 중 사용 | 개발자가 문항과 답안을 열람할 수 있고 별도 비공개 holdout은 없다. 이 세트에 맞춘 개선이 미지의 사용자 질문에도 일반화된다는 근거는 아니다. |

전후 비교에는 같은 문항·Corpus·판정 기준을 사용하고 유형별 결과를 함께 본다. 문항 하나가 22문항의 답변 가능 여부 정확도를 약 4.5%p 바꾸므로 작은 점수 차이를 일반적인 성능 개선으로 단정하지 않는다.

## 데이터 구조

[gold.jsonl](gold.jsonl)은 한 줄에 한 문항을 저장한다.

| 필드 | 의미 |
| --- | --- |
| `id` | 문항 식별자 |
| `inputs.question` | 사용자 질문 |
| `inputs.history` | 후속 질문에 제공하는 고정 대화 이력 |
| `expectations.answerable` | 고정 Corpus에서 답변에 필요한 근거를 확보할 수 있는지 |
| `expectations.answer` | 모범 답안 |
| `expectations.required_points` | 답변이 충족해야 하는 의미 기준 |
| `expectations.optional_points` | 선택적으로 포함할 세부 설명·수치 |
| `expectations.unacceptable_claims` | 오답으로 판단할 주장 |
| `expectations.evidence` | 근거 URL·인용문·문서 버전·본문 해시·섹션 |
| `metadata` | 문항 유형과 Corpus·참조 인덱스 정보 |

[manifest.json](manifest.json)은 문항 수, 유형별 구성, 기준 Corpus 스냅샷·인덱스와 파일의 SHA-256 해시를 기록한다. 기준 Corpus는 27개 문서와 454개 청크로 구성된다.

## 평가 기준

- 모범 답안과 문장 일치를 요구하지 않고 필수 요점과 금지 주장을 기준으로 판단한다.
- 질문에서 요구하지 않은 실험 수치를 모두 나열할 필요는 없다. 수치를 제시하면 단위·조건·대상을 정확히 연결해야 한다.
- 특정 실험의 가격·성능·지원 범위를 현재 또는 모든 환경의 보장으로 확대하지 않는다.
- 근거 부족 문항은 답을 추측하지 않고 자료의 한계를 밝히는 것이 정답이다. 해당 문항의 긍정 근거 인용문은 비어 있으며, 표준 근거 부족 응답도 수용한다.
- Corpus가 갱신되어 새로운 근거가 생기면 답변 가능 여부와 기대 답안을 함께 재검토한다.

후속 대화 문항 `gold-018`은 고정된 사용자·assistant 이력과 마지막 질문을 함께 입력한다. 첫 답변을 매번 생성하는 전체 대화 평가와 구분하며, QA 프로필의 이력 한도가 해당 대화 한 쌍을 보존해야 한다.

현재 Eval Harness는 사람과 모델이 같은 [gold-ordinal-v1 rubric](../../../apps/knowledge/src/elice_knowledge/data/rubrics/gold-ordinal-v1.json)으로 정확성·완전성·근거 충실도·질문 적합성을
**0(부족)·1(부분 충족)·2(충분)**로 직접 채점한다. 모델은 Ragas DiscreteMetric을 사용한다.
완전성은 required_points의 의미 충족을 보고 optional_points의 누락은 감점하지 않는다.
근거 충실도는 실제 생성에 전달된 문맥만 사용한다. N/A·오류는 0점이 아니며 pass/fail 임계값은 없다.

문항별 사실 기준은 JSONL에, 공통 항목·척도·anchor는 버전 있는 rubric 파일에 둔다.
manifest의 default_rubric_id는 기본 기준을 가리키며 실제 채점 프로필에 rubric 원문·해시를 고정한다.
이 rubric 변경은 질문·모범 답안의 재검수를 대신하지 않는다.

누적 검색·최종 문맥의 Context Recall·Precision과 답변 비율 지표는 `--diagnostics`로 별도 실행한다.
URL·인용문은 검증된 대표 근거이지 유일한 정답 근거 목록은 아니다. 대체 근거도 같은 사실을
뒷받침하면 인정할 수 있다. 합성 답안·공통 rubric·LLM 판정의 편향이 남고 모든 오류 검출을 보장하지 않는다.
새 척도의 사람–모델 정합성은 아직 측정하지 않았다. 상세 계약은 [평가 스키마](../../../docs/evaluation-schema.md)를 따른다.

보안·악용·역할 유지에 관한 대응은 [🦾 Iron Set](../iron_set/README.md)으로 구분해 집계한다.

## MLflow 등록

질문·기대 답안은 이 폴더의 JSONL에서 수정하고 저장소 루트에서 등록한다.

```bash
uv run --project apps/knowledge python tools/evaluation/register.py --dataset gold --dry-run
uv run --project apps/knowledge --env-file .env.dev python tools/evaluation/register.py --dataset gold
```

`elice-techblog-gold` Dataset을 하나씩 유지하며, 재등록하면 저장소 내용으로 갱신한다.
등록 결과의 Dataset ID를 해당 서버의 평가·조회에 사용한다. 등록은 모델 호출을 하지 않는다.
